# Transcript ảnh slide deck02 + deck03 (đối chiếu sheet api.txt)

Quy ước: `↳` = trường con của `data`; `↳↳` = trường con cấp 2. NN: O = bắt buộc, X = không bắt buộc.
Phần "Method/Path" ghi đúng như ảnh; nếu ảnh không có thì ghi "(không hiển thị trong ảnh)" kèm tên tab sheet tương ứng.
Phần "So sánh" liệt kê khác biệt với tab sheet tương ứng (bỏ qua khác biệt định dạng thuần túy).

## deck02/s05_1.png — signup (Bản cập nhật 17/10 chỉnh sửa lỗi typo)

Dòng tiêu đề trong ảnh: "Bảng đặc tả Input và Output chi tiết cho API Đăng ký tài khoản (POST /api/auth/signup):"

Method/Path trong ảnh: **POST /api/auth/signup** — Tab sheet: `1.1 signup`

### Input
| NO | Tên parameter | Type | NN | Mô tả |
|---|---|---|---|---|
| 1 | Content-Type | string | O | (Header) Mặc định là application/json |
| 2 | full_name | string | O | Họ và tên đầy đủ của người dùng |
| 3 | phone | string | O | Số điện thoại đăng ký (đúng định dạng số VN) |
| 4 | password | string | O | Mật khẩu tài khoản (Tối thiểu 6 ký tự) |
| 5 | gender | string | X | Giới tính: male (nam), female (nữ), other (khác) |

### Output
| NO | Tên parameter | Type | NN | Mô tả |
|---|---|---|---|---|
| 1 | code | string | O | Mã phản hồi hệ thống (1001: Thành công) |
| 2 | message | string | O | Thông báo kết quả (Created successfully) |
| 3 | data | object | O | Thông tin tài khoản người dùng vừa tạo |
|  | ↳ user_id | int | O | ID tài khoản được sinh tự động trong cơ sở dữ liệu |
|  | ↳ full_name | string | O | Họ và tên người dùng |
|  | ↳ phone | string | O | Số điện thoại đã đăng ký |
|  | ↳ gender | string | X | Giới tính của người dùng |
|  | ↳ role_id | int | O | Phân quyền tài khoản (Mặc định: patient) |
|  | ↳ is_active | int | O | Trạng thái hoạt động của tài khoản (1: active) |
|  | ↳ created_at | string | O | Thời gian tạo tài khoản (Chuẩn datetime) |

**So sánh:** KHỚP hoàn toàn với tab `1.1 signup`.
(Ghi chú nội tại, cả ảnh lẫn sheet: role_id kiểu int nhưng mô tả "Mặc định: patient" là chuỗi.)

## deck02/s09_1.png — login (bản edit 11/10/2026)

Dòng tiêu đề trong ảnh: "Bảng đặc tả Input và Output chi tiết cho API Đăng nhập tài khoản (POST /api/auth/login):"

Method/Path trong ảnh: **POST /api/auth/login** — Tab sheet: `1.2 login`

### Input
| NO | Tên parameter | Type | NN | Mô tả |
|---|---|---|---|---|
| 1 | Content-Type | string | O | (Header) Mặc định là application/json |
| 2 | phone | string | O | Số điện thoại đăng nhập |
| 3 | password | string | O | Mật khẩu tài khoản |

### Output
| NO | Tên parameter | Type | NN | Mô tả |
|---|---|---|---|---|
| 1 | code | string | O | Mã phản hồi (1000: Thành công) |
| 2 | message | string | O | Thông báo kết quả |
| 3 | data | object | O | Chứa thông tin đăng nhập và token |
|  | ↳ token | string | O | JWT Token dùng để xác thực các request sau này |
|  | ↳ user_info | object | O | Thông tin cơ bản người dùng, (bao gồm user_id, display_name: họ và tên VD tên đầy đủ là Nguyễn Văn A thì chỉ hiện Nguyễn A, role_id) / Mục địch của user_info để tiện cho Frontend, đồng thời bao gồm role_id để tiện điều hướng theo role |
|  | ↳↳ user_id | string | O | ID định danh tài khoản |
|  | ↳↳ full_name | string | O | Họ và tên |
|  | ↳↳ phone | string | O | Số điện thoại |
|  | ↳↳ role_id | string | O | ID định danh vai trò phân quyền |

**So sánh:** KHỚP hoàn toàn với tab `1.2 login` (kể cả lỗi chính tả "Mục địch").
(Ghi chú nội tại, cả ảnh lẫn sheet: mô tả user_info nói "display_name" nhưng trường con là `full_name`; user_id/role_id ở đây kiểu **string**, trong khi signup/profile dùng **int**.)

## Tổng kết

- 24/24 ảnh (deck02: 9, deck03: 15) khớp nội dung với tab sheet tương ứng: cùng tham số, kiểu, cờ NN, cấu trúc lồng, mô tả. Ảnh thực chất là chụp màn hình các tab sheet.
- Khác biệt duy nhất: ô ghi chú "Lệch so với sheet DB (enum)" ở dòng `career` (PUT profile input) có trong sheet nhưng không có trong ảnh s31.
- Chỉ 2 ảnh hiển thị method/path (signup: POST /api/auth/signup; login: POST /api/auth/login). 22 ảnh còn lại không có method/path — phải suy từ tên tab sheet.
- Lỗi/điểm bất nhất tồn tại ở CẢ ảnh và sheet (không phải lệch ảnh-sheet, nhưng cần xử lý trước khi code):
  - `ffull_name` trong output create_user (admin01).
  - login: user_id/role_id kiểu string; signup/profile/admin users dùng int.
  - login: mô tả user_info nói `display_name` (rút gọn "Nguyễn A") nhưng trường con thực tế là `full_name`.
  - signup: role_id kiểu int nhưng mô tả "Mặc định: patient".
  - set_role_permissions trả code 1000, các API tạo khác trả 1001.
  - GET roles không trả parent_role_id; create_staff output không trả room_id.
